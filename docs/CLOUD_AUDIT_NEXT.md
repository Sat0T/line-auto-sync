# Cloud取り込み監査の次の確認 — 2026-11-25

本書は変更内容と将来の証拠設計。2026-11-25には正規の実アクセスから修正版を適用し、新しいcloud-synthetic入力1件の本人Gmail配送まで確認した。実適用・元版退避・限定ルール追加の記録は[WORK_HANDOFF](WORK_HANDOFF.md)を参照。自然なChatGPT結果作成と取り込み保存、iPadのロック中配送は別に未確認。

## 今回確認した不具合と修正

送信結果が不明でmail_stateがsendingになった際、従来のSent照合は件名・本人From/Toだけで一致させていた。同じ件名の別本文を与える合成試験で、送信成功へ誤回復することを再現した。

Core.forwardは回復時にも保存本文のハッシュを検証してから、その本文をmailer.findへ渡す。App側はfull MIMEを読み、本人From/To・件名・復元した本文のすべてが一致する候補が1通だけある場合に限り採用する。候補検索が途中のページ、複数の本文一致候補、本文不一致、保存本文の破損はsendingのまま保持し、送信し直さない。検索上限を超えた候補は自動的に全件走査せず保留する。

厳密本文照合に必要なMIME互換性も確認した。format=flowedを復元する処理が、末尾改行のsplit sentinelをもう1行として出力していたため、正しい本文でも不一致になった。末尾sentinelだけを除外する最小修正で、折返し復元後の本文一致を維持する。本文全体のtrimや、本文ハッシュを無視する回復は行わない。

前向き監査の境界判定も修正した。従来は境界以前のメールへの監査だけを抑え、本文の解析と結果処理には進んでいた。境界以前は本文復元・結果処理前に除外し、internalDateが欠落・不正・安全な整数でない場合も処理しない。境界以降の保存済み監査は再処理せず、部分失敗と終了監査失敗からの再開、別メールで届く将来の重複結果の判定は維持する。旧対象への遡及処理は行わない。

NodeのGAS合成試験は18件成功。修正前には旧メールの処理経路への再投入を合成試験で再現した。修正後は古い未処理・完了済みメールの除外、不正時刻、境界ちょうどの新規メール、完了監査の再処理回避を確認した。既存の本文照合・結果監査・重複排除・途中失敗復旧の試験も通過。修正版は実HEADと既存Web配備へ適用し、自然な保守実行と架空入力配送を確認済み。新しい結果メールの実取り込みと監査行保存は、結果作成待ちで未確認。

## 将来の新しい架空入力1件で残す証拠

1. 実行前に、既存の配備版・受理するsource・送信先本人・入力1件・未使用の試験ID・試行上限・停止条件を私用記録へ固定する。Cloudだけで作るfixtureはcloud-synthetic由来と明示し、実LINEのDB取得・ロック中配送の成功へ数えない。既存の実LINE IDや旧2件を使って証拠を作り直さない。Cloud用source/IDの安全な受理方法が未確認なら、その確認前に送信しない。
2. 受信台帳のsource、対象ID、batch、本文の対応と、本人宛入力Gmailの実ID・internalDate・full MIME本文を私用で照合する。HTTP 2xxやOK、mail_stateだけでGmail到着済みとはしない。MailAppの正常応答と、同一本文のメールが実際に存在する証拠を分ける。
3. 実物を特定した既存のChatGPT定期ルールに必要な1件限定条件だけを適用する場合も、既存頻度・無関係な通知は保つ。自然な次の実行を待ち、手動実行で自然起動の証拠を代替しない。現在のツールには、対象hostedタスクを直接特定して実行理由を取得する確認済み経路がない。別のCodex cronを同じタスクとみなさない。
4. ChatGPT側で実際に取得できた実行ID・起動理由・その実行の結果メール作成ツール記録を保存する。取得できなければ未取得のまま。本文に自己申告された実行IDや独自UUIDは、ネイティブ実行・自然起動の証明にしない。
5. 新しい結果メールの実IDと内容、GAS result_import_auditの開始/終了、results/messagesの結果ハッシュ、対象tasksの行を照合する。監査機能が未配備なら取得できる証拠の前提にしない。監査開始境界より古いメールへ遡及行を作らず、旧対象を再解析しない。

## 実行識別情報の意味

- gas_import_attempt_id：GAS内で生成する相関用UUID。同じ値を私用実行consoleと監査表で対応付けられるが、GoogleやChatGPTが発行したネイティブ実行IDではない。
- trigger_uid_observed：イベントから実際に取得したトリガー識別子。個別実行IDや、ChatGPTの自然起動理由を表さない。
- gas_native_execution_id / chatgpt_run_id / chatgpt_start_reason：実際の取得経路がなければnull。後付けの推測値を保存しない。
- 正しいタスク・期限・結果ハッシュとcomplete状態：保存内容の対応の証拠であり、それだけではChatGPTの自然起動の証明ではない。

結果保存と監査は非原子的。監査開始に失敗すれば保存を開始せず、終了監査に失敗した場合も成功として返さない。開始のみの監査は完了不明として扱う。部分保存の再開は同じ結果ハッシュで重複を増やさず、本人の完了状態を保持する。新しい実機・Cloud試験の実結果が得られるまで、自然な完全自動解析の証拠不足とMVPの未完成判定は維持する。公開するのは結論・コード・架空fixtureだけとし、実ID・実ハッシュ・非公開URL・認証情報・会話・生ログは私用のまま保持する。
